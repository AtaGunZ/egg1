# Rule authoring

* Pipeline: `python -m bimcheck.regulation.extract` (PDF -> `regulation/articles.json`; colour spans: grey=deleted, red=added, black/blue=kept; tables and closing-sentence routing are curated in `regulation/overrides.json` and verified against the PDF) then `python tools/regulation/build_rules.py` (spec `tools/regulation/rules_spec.py` + articles -> `rules/kayseri.rules.json`, `rules/RULES.md`). `text_tr`, `page` and `revision` are always derived from articles.json.
* Add/change a rule: edit `rules_spec.py` with `R(article, paragraph, item, ...)` and a check from `mn/mx/rng/eq` (declarative, measure names from CONTRACTS section 1 only) or `cu(custom_id, ...)` (id from the fixed list in `catalogue.ALLOWED_CUSTOM_IDS`; parameters go in `check.extra`), or `man(...)` for manual rules. Rule ids: `KBB-<article>-<paragraph>[-<item>]`; item letters are ASCII-slugged (ç=cc, ğ=gg, ı=ii, ö=oo, ş=ss, ü=uu, `a.1` -> `a-1`).
* Per-project overrides: `bimcheck.regulation.apply_overrides(cat, {"KBB-28-4": {"limit": 2.5}})`; another municipality: build its own catalogue file (prefix e.g. `IST`) and combine with `merge_catalogues`; always run `validate_catalogue`.
* New regulation PDF: copy `extract.py` settings (PDF path, colours, `BODY_LAST_PAGE`), add its `overrides.json`, check `extract_report.json` warnings and render suspicious pages to PNG for a visual check.
